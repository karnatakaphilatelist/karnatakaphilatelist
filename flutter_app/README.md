# Philatrail — Flutter app (in progress)

## Status

This directory holds the parts of the Flutter app that are safe to hand-write
without the Flutter/Dart tool itself: domain models (`lib/models/`, mirroring
`src/types/index.ts`), the theme (`lib/theme/app_theme.dart`, mirroring the
reconciled `DESIGN.md`/`globals.css`), and `pubspec.yaml`.

**What's deliberately missing: `android/` and `ios/` platform folders.**
Those are normally generated by `flutter create` from templates tied to the
installed Flutter/Dart version — Gradle wrapper binaries, the Xcode
`.pbxproj` project file, signing config, manifest/plist boilerplate. Hand-
writing those from scratch is how you end up with a project that looks right
and doesn't build. They have not been faked here.

## The one blocker

`flutter create` needs the Dart SDK and engine binaries, which `flutter`
downloads from Google Cloud Storage on first run. That host is blocked by
this sandbox's egress policy (confirmed: cloning the Flutter SDK repo itself
from GitHub works fine; the first-run binary download gets a 403). Two ways
to unblock this:

1. Get `storage.googleapis.com` (or wherever this session's proxy logs the
   blocked host) added to this environment's allowlist, then `flutter create .`
   can be run for real in this directory and its android/ios output merged in.
2. Run `flutter create .` once in this directory on a machine that has normal
   internet access (yours, or CI), commit the generated `android/`/`ios/`
   folders, and hand it back — everything in `lib/` here is written to drop
   straight into that scaffold.

## Non-negotiable once `android/` exists: Play Store continuity

Per `CLAUDE.md` §2C — before the first real build:
- `android/app/build.gradle`'s `applicationId` must be set to
  `app.vinvi.philatrail`, matching the existing Capacitor app
  (`android/app/src/main/java/app/vinvi/philatrail/MainActivity.java` and
  `android/app/build.gradle` at the repo root) character-for-character.
- The `.aab` must be signed with the **same upload keystore** already in use
  for the live Play Console closed-testing track.
- `versionCode` must be strictly higher than what's currently live.

Any mismatch resets the 14-day closed-testing requirement to zero — verified
against current Play Console behavior, not assumed.
