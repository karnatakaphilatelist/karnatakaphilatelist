# Philatrail — Flutter app (in progress)

## Status

Real Flutter project, generated by `flutter create --org app.vinvi
--project-name philatrail .` (Flutter 3.50.1 / Dart 3.14.0) — the egress
blocker below is resolved, so `android/` and `ios/` are no longer
hand-written stand-ins. They're the genuine Gradle/Xcode scaffold, with the
hand-written domain models (`lib/models/`, mirroring `src/types/index.ts`)
and theme (`lib/theme/app_theme.dart`, mirroring the reconciled
`DESIGN.md`/`globals.css`) dropped in on top untouched.

## Resolved: the GCS/pub.dev blocker

`flutter create` needs the Dart SDK/engine (Google Cloud Storage) and package
index (`pub.dev`) on first run; both were blocked by this sandbox's egress
proxy. Fixed by adding `storage.googleapis.com`, `*.googleapis.com`, and
`pub.dev` to this claude.ai account's Settings → Capabilities → "Allowed
websites" list (personal-plan equivalent of the org-level network allowlist).
`flutter --version` and `flutter create` both now work in this sandbox.

## Still open before a real build — Play Store continuity (`CLAUDE.md` §2C)

- **`applicationId`** — ✅ done. Generated as `app.vinvi.philatrail` in
  `android/app/build.gradle.kts` (`namespace` and `defaultConfig.applicationId`
  both set), matching the live Capacitor app
  (`android/app/src/main/java/app/vinvi/philatrail/MainActivity.java` and
  `android/app/build.gradle` at the repo root) character-for-character.
- **`versionCode`** — ✅ done. Per the Play Console closed-testing track
  (checked 24 Nov 2026): release 5 (v1.0.2) is live to testers, release 7
  (v1.0.4) is drafted but not yet sent for review. `pubspec.yaml`'s build
  number is set to `8` — strictly higher than both, so it's safe even if
  release 7 ships before the Flutter app does. Re-check this value again
  right before the actual first build, since the track may have moved on.
- **Signing** — ✅ wired, pending a CI run. `android/app/build.gradle.kts`
  now has a real `release` signing config that reads
  `KEYSTORE_FILE`/`KEYSTORE_PASSWORD`/`KEY_ALIAS`/`KEY_PASSWORD` from the
  environment, falling back to the debug key only when they're absent (so
  local `flutter run --release` still works without them). The actual
  keystore was never available here to begin with — per `docs/RELEASE.md`
  it only ever exists as a local `.jks` on the maintainer's Mac and as four
  **write-only** GitHub Actions secrets (`ANDROID_KEYSTORE_BASE64`,
  `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`)
  already used by the Capacitor app's `android-release.yml`. Rather than
  needing a copy of it, `.github/workflows/flutter-android-release.yml`
  reuses those same four secrets directly in CI, so the keystore never has
  to leave GitHub or pass through this sandbox. Run that workflow (Actions
  tab, manual dispatch) to produce a real signed `.aab`.

Any mismatch on any of the three resets the 14-day closed-testing
requirement to zero — per current Play Console behavior, not assumed.
